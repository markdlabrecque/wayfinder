# Workplan: Align Pi development workflow with Claude Code policy

> System of record: **Filesystem**

## Objective

Bring the global Pi workflow at ~/.pi/agent/extensions/development-workflow and its bundled agents into behavioral parity with ~/.claude/CLAUDE.md and ~/.claude/agents/*.md, adapting Claude-specific tool names to Pi rather than copying them literally. The current Pi implementation has substantial drift: it runs Implementer before Test Writer, defaults to three review cycles, forces one local Ollama model for every role and the foreground orchestrator, has much weaker role contracts, lacks the documented dirty-tree/branch/tracer-bullet/root-cause/expiring-skip guardrails, and explicitly disallows the worktree-based parallel orchestration described by the Claude policy. Its documentation also names an obsolete oMLX model while source uses ollama/qwen3.6-pi:35b-a3b, and the current workflow test baseline is red (51/53) because model assertions no longer match implementation. Preserve the good existing properties: foreground planning, no sub-orchestrator, stable workflow IDs, original-Implementer review bounces, durable state, child authority boundaries, mutation locks, diagnostics, and trusted system-of-record writes. The Wayfinder checkout also contains an unrelated untracked .pi/workplans/workflow-1785297865246-12414c.md; do not modify or delete it.

## Action Plan

1. [ ] Establish the policy source of truth before implementation: create a Pi-native global policy at ~/.pi/agent/AGENTS.md that mirrors the behavioral rules in ~/.claude/CLAUDE.md while translating Claude-only concepts (Agent tool, SendMessage, Context7 MCP) into Pi equivalents; document precedence so project AGENTS.md/CLAUDE.md overrides global defaults, and add a lightweight parity checklist or sync test to prevent silent drift between the two global policies.
2. [ ] Repair and freeze the existing baseline before changing behavior: update the stale oMLX/Ollama model assertions and contradictory README text so source, tests, and documentation describe the same current behavior; run all development-workflow and subagent tests and require a fully green baseline before adding new red tests.
3. [ ] Write state-machine tests first for a versioned TDD sequence used by new workflows: foreground plan/spec -> Test Writer red tests -> Implementer green implementation -> Reviewer -> Reporter, with fixing routed back to the original Implementer and then to Reviewer. Preserve explicit migration/recovery semantics for active version-3 workflows rather than silently reinterpreting their current stage.
4. [ ] Change workflow state and child authority rules to implement the new sequence. Give Test Writer authority only to record test files plus red-test evidence and advance to implementation; give Implementer authority to record implementation files plus green full-suite evidence and advance to review; keep Reviewer read-only and Reporter unable to edit production/tests. Add clear stage names or stage metadata so pre-implementation red testing cannot be confused with post-implementation verification.
5. [ ] Add enforceable TDD gates, not prompt-only claims: Test Writer cannot hand off until the targeted tests execute and fail for the expected behavioral reason; Implementer cannot hand off with any red test and must record the project’s full-suite command/result; disputed tests stop and escalate to the foreground Orchestrator instead of being edited by Implementer. Cover malformed, missing, stale, and contradictory evidence in tests.
6. [ ] Replace the bundled role prompts with Pi-adapted equivalents of ~/.claude/agents/test-writer.md, implementor.md, reviewer.md, and reporter.md. Preserve their exact role boundaries, ambiguity/escalation rules, handoff artifacts, test evidence requirements, read-only review behavior, and faithful reporting. Add shared instructions for minimal targeted changes, root-cause fixes, tracer bullets, project-convention discovery, premise verification, and expiring guards for skips/TODOs/ignored tests.
7. [ ] Align model routing with the Claude-role analogs using Pi's GPT-5.6 family: map Claude Sonnet roles to `openai-codex/gpt-5.6-terra` (Test Writer, Implementer, and Reporter), and map Claude Fable/Opus roles to `openai-codex/gpt-5.6-sol` (Reviewer and any equivalent high-judgment planning/orchestration role). Stop forcing the current local Ollama model across the workflow. Resolve and authenticate each role model at dispatch with actionable errors, persist the effective role model for resume, and test that explicit supported overrides take precedence without allowing accidental model drift across implementation or review rounds.
8. [ ] Change review routing to a default maximum of two rounds. Require Reviewer to run the full project gate first, classify findings into blocking versus follow-up categories, bounce must-fix and five-minute items to the original Implementer, and escalate any still-critical failure after round two. Persist the “could use more review passes” marker when non-critical leftovers remain after the cap and require Reporter to include it.
9. [ ] Strengthen Reviewer task construction so the foreground Orchestrator passes the approved spec, red-test evidence, implementation diff, green-suite evidence, and a named suspected weakness derived from any shortcut or high-risk premise. Add tests ensuring generic review prompts are rejected or augmented and that Reviewer findings cite verification rather than merely restating implementation claims.
10. [ ] Make Reporter completion real and auditable: add a reporter-owned structured result field/action through which Reporter returns the exact final post; have the trusted extension write that content to the configured project system of record, falling back to docs/reports/YYYY-MM-DD-<task-slug>.md when project instructions define no other destination. Include built work, command/result evidence, review verdict, all deferred follow-ups, and the review-cap warning; ensure posting failure preserves technical completion and recovery state.
11. [ ] Add repository preflight to the foreground workflow contract and state: inspect branch and git status before planning or mutation, surface pre-existing dirty paths, and require explicit acknowledgement before continuing without touching them. Default new work to a feature branch off the project’s base branch while allowing project instructions to override branch/test conventions. Record the preflight snapshot so mutation ownership protects files that were already dirty.
12. [ ] Carry the remaining global Claude guardrails into Pi’s foreground and role prompts, with targeted extension guards where safely enforceable: never access or write production servers; Chromium for automated browser work and Firefox-oriented manual instructions; end-to-end validation for the daily-log post-commit hook; uv sync --extra dev when dev dependencies are optional extras; user-scope default for cross-project integrations; shortest-correct user output; and no automatic continuation from an answered question without confirmation.
13. [ ] Support the documented parallel-batch model without creating sub-orchestrators: the foreground Orchestrator alone may coordinate multiple issue pipelines in separate worktrees, only when parallel work is explicitly requested. Extend workflow/batch metadata and prompts to record each worktree, file ownership, sibling-owned files, and shared contracts; land shared infrastructure first; bound concurrency by hot-file contention; and require rebase/update plus full gates on the merged state. Remove the blanket “No Git worktrees” restriction while retaining cross-process mutation safety and add tests proving ownership is isolated correctly across worktrees and stable for a resumed Implementer.
14. [ ] Update orchestration prompts and documentation to state when the full pipeline may be deliberately skipped (only trivial typo/config-one-line work, with the Orchestrator saying so), prohibit forks/sub-orchestrators as pipeline stages, pass artifacts rather than conversation history between fresh stage contexts, and describe recovery for active legacy workflows, orphaned workflow workplans, cancellation, blocked review, and cleanup.
15. [ ] Expand regression coverage across development-workflow and subagent extensions: new/legacy stage migration, red and green gates, wrong-test escalation, two-round review exhaustion, original-Implementer resume, role tool restrictions, role-model selection, exact Reporter content, dirty-tree acknowledgement, project-policy precedence, worktree ownership, parallel contention, expiring skips, diagnostics redaction, terminal compatibility, and cleanup. Mutation-test the validation gates by deliberately breaking each one and confirming its test fails before reverting.
16. [ ] Run the complete validation matrix after implementation: all Node test files for development-workflow and subagent, extension load/list-model checks, TypeScript/static checks used by this installation, and manual end-to-end tracer workflows for one successful change, one disputed test, one two-round blocked/escalated review, one dirty-tree preflight, and one two-worktree parallel batch. Capture results in a dated report and update README/rollback instructions with the final verified commands and model requirements.
