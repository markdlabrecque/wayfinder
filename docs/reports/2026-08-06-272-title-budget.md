# #272 — budget the `HtmlSink` `<title>` accumulation

Follow-up 1 from #258 (`docs/reports/2026-08-02-extract-only-tracer.md`).

## Problem

`HtmlSink` accumulated `<title>` text via
`state.title.get_or_insert_with(String::new).push_str(chars)` in
`src/extract.rs`'s `process_token` with **no budget check**. A document with
an arbitrarily long `<title>` could grow that buffer without limit while every
other budget in the extractor was enforced — the one unbudgeted allocation
path left in the HTML extractor, and the obvious way to defeat
`max_output_bytes` on the extract route.

## Fix

The title is metadata, not body output, so it can't go through
`Budget::push_str` (which would land it in `budget.output_text()`, i.e. the
body text). Instead a new `SinkState::push_title` helper charges the title
text against the same `max_output_bytes` / `max_output_scalars` ceilings as
the body via the private `Budget::charge_output`, without accumulating into
the body text — exactly the pattern captured attribute values already use
(#259). A budget violation there propagates through the existing
bottom-of-`process_token` error match (set `state.error`, signal abort).

## Bonus coverage

A `<title>` long enough to exhaust a tiny `max_output_bytes`, with the overrun
inside one long character run and no following tag token, is also the scenario
that proves the html5ever early-abort check (`||
tokenizer.sink.state.borrow().error.is_some()` after every chunk): a budget
blown mid-character-run has no tag to carry `TokenSinkResult::Script`. That
check was the untested **follow-up #4** from #258's tracer report; the new
test covers it too.

## Status mapping (documented budget-violation status)

`ExtractError::OutputTooLarge(_)` maps to **HTTP 400**
(`extraction-output-too-large`) per the `From<ExtractError> for WfError`
impl in `src/extract.rs`. The new test asserts the `ExtractError` variant
directly (`OutputTooLarge(OutputLimitKind::Bytes)`), which is the
budget-violation status this extractor-internal API exposes.

## Test + mutation

- `title_accumulation_is_charged_against_the_output_budget` in
  `tests/html_extractor.rs`: a 1000-byte `<title>` under
  `max_output_bytes = 10` must fail `OutputTooLarge(Bytes)` rather than
  accumulate without limit.
- **Confirmed red for the right reason** before the fix: extraction returned
  `Ok` with the full 1000-character title accumulated.
- **Mutation-tested**: removing the `charge_output` call in `push_title`
  made the named test fail (title accumulated unbounded → `Ok`); reverted.
