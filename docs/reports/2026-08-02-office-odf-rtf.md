# Issue #260 — office/ODF/RTF extractors: DOCX, PPTX, XLSX, ODS, ODT, ODP, RTF

Date: 2026-08-02
Branch: `markdlabrecque/issue-260-office-odf-rtf`
Follow-up to: `docs/reports/2026-08-02-extract-only-tracer.md` (#258,
extractOnly route, plain text + HTML) and `docs/reports/2026-08-02-extraction-phase-0.md`
(#257, budgets/contract). Blockers #257 and #258 are both closed.

## What shipped

Seven office-format extractors on top of #258's `/update/extract?extractOnly=true`
route, each verified against captured Solr 9.10.1 ground truth rather than
assumed. All seven run under #257's existing budgets (`Budget`, `ZipBudget`,
deadline); none construct an unbounded DOM.

- **DOCX / PPTX** — bounded `zip` + streaming `quick-xml`. `collect_zip_parts`
  makes one bounded pass: `ZipBudget::admit()` per entry (path, count, declared
  ratio, declared cumulative), `charge_actual()` per chunk for the *wanted*
  entries only. DOCX walks `w:p`/`w:t`/`w:pStyle`, mapping heading levels 1–6
  to `<h1>`–`<h6>`. PPTX sorts slides numerically and renders each as
  `<div class="slide-content">…</div>` + `<div class="slide-master-content" />`.
- **XLSX / ODS** — `calamine::Reader::worksheets()`, one `<div>` per sheet with
  an `<h1>` sheet name, a `<table>` (XLSX wraps `<tbody>`, ODS does not), and a
  leading `\t` before each `<td>` reproduced literally (finding 126). XLSX reads
  `docProps/core.xml` for title/author (calamine does not surface them); ODS
  reads `meta.xml` (empty in the fixture).
- **ODT / ODP** — bounded `zip` + streaming `quick-xml`. ODT maps `text:h` /
  `text:p`; the ODF serialiser's quirk (finding 126) is that a paragraph carries
  its own trailing `\n` and a heading carries none, so consecutive paragraphs
  are separated by exactly that trailing newline. ODP maps each `draw:page` to a
  `<div><p>…</p>\n</div>\n`.
- **RTF** — walks the `rtf_parser::lexer::Lexer` token stream directly, *not*
  the `RtfDocument` API (which collapses `\par` boundaries and loses paragraph
  structure). Bold is tracked through the group stack; header destinations are
  skipped; one `<p>` per `\par`.

Supporting changes:

- **`ContentType`** gained `Docx`/`Pptx`/`Xlsx`/`Odt`/`Odp`/`Ods`/`Rtf`, and
  `refine_zip_kind()` opens a detected archive to resolve it to an office
  variant (or leaves it `Zip` for an unrecognised package).
- **`extract_document()`** was restructured for binary formats: no charset
  decode (raw bytes are handed to the extractor), and
  `ExtractedDocument.charset_label` became `Option<String>`. `ExtractRender`
  branches on charset presence so binary formats emit no `Content-Encoding`.
- **Four dependencies**: `zip@8` (deflate only), `quick-xml@0.36`,
  `calamine@0.26`, `rtf-parser@0.3`.

## Fixtures and findings

Twenty-one new fixtures captured against real `solr:9.10.1` (container on port
9020, core `extract260`): seven formats × {`xml`, `text`} = 14 success captures,
plus seven malformed-input 500s. A `#260` block was appended to
`solr-ref/capture.sh` and 21 rows to `solr-ref/manifest-multipart.tsv`; the
`CAPTURED_EXTRACT_FIXTURES` trip-wire was raised to 31. Inputs are tiny
synthetic documents generated by `_gen_office.py` (python-docx/python-pptx/
openpyxl/odfpy + a hand-written RTF), with python-docx/pptx thumbnails stripped
so they don't drift, plus `broken.*` (64-byte truncations / a multi-GB `\bin`
RTF) and `bomb.docx` (a DOCX-shaped zip-bomb, see Containment below).

Four new findings appended to `docs/solr-ref-findings.md`:

- **124** — `extractFormat=text` leading-newline count is driven by the head
  `<meta>` count (+2 with a non-empty title, else +4). Finding 121's
  constant-13 holds only for plain-text/HTML; office formats break it, and the
  count is not independently reproducible once Wayfinder's narrower metadata
  (finding 125) yields a different meta count than Tika.
- **125** — Office metadata is rich and format-specific; Wayfinder's narrow
  promise (six envelope keys + `Content-Type`, plus title/author when reliable)
  is a documented, normalized divergence — the office counterpart of
  `X-Parsed-By` (finding 123), larger cardinality.
- **126** — Each office family emits a distinct, reproducible XHTML body shape
  (catalogued per format above).
- **127** — Malformed-input 500 envelopes: truncated archives choke the zip
  reader (`InvalidFormatException`); RTF is lenient and only a multi-GB `\bin`
  declaration makes it 500 (`EOFException`).

## Differential harness

`tests/common/diff.rs::normalize_extract` gained an office-aware scope (the
plain-text/HTML path — `X-Parsed-By` + `shape="rect"` — is unchanged, so the
three existing guard tests stay green). For office content types it:

- strips every `<meta>` from the XHTML `<head>` (leaving `<title>` and `<body>`
  to compare),
- collapses the leading-newline run of `extractFormat=text` bodies (finding 124),
- keeps only the six envelope keys in `file_metadata`.

Detection keys off the `Content-Type`/`stream_content_type` envelope value, so
it only fires for the seven office MIME types; a non-office envelope with no
ratified marker still comes back untouched. All 14 success rows were added to
`ACCEPTED_DIVERGENCES_MULTIPART`, and four new guard tests pin the office scope:
head-meta/envelope stripping, text leading-newline collapse, an
over-normalisation guard (a real body difference survives), and a no-touch
guard when an office envelope is already normal.

The seven malformed (500) rows match at the status + `error.code` level, the
same treatment every other error fixture gets: `normalize()` strips Tika's
Java-specific `error.msg`/`metadata`/`trace`, leaving the comparable 500
envelope. Wayfinder returns 500 for all seven (zip readers fail with a `Parse`
error; RTF fails lexing) — the same status Tika returns, for the same reason.

The hermetic differential (`extract_multipart_manifest_matches_captured_fixtures`)
is green across all 21 rows.

## Test coverage

- `tests/office_extractor.rs` — a fixture-derived unit suite: for each format,
  `extract_document` is called directly (no HTTP) and its `content_type`,
  `title`, `author`, `charset_label`, `body_xhtml`, `body_text` are asserted
  against values *derived* from the committed fixtures (`<body>…</body>` lift
  for XHTML; leading-newline + title-prefix strip for text), never hand-typed.
  This pins each extractor field-by-field; the differential separately proves
  the full rendered envelope end to end.
- **Containment tests** in the same file: malformed inputs (`broken.*`) must
  return `Err`, never panic or false-succeed; and `bomb.docx` (a DOCX-shaped
  package whose `word/document.xml` is 1 MiB of zeros, ~1000:1 declared ratio)
  is rejected by `ZipBudget`'s declared-ratio guard at admission time, before a
  byte is decompressed. The ratio guard was **mutation-tested**: disabling it
  turns the bomb test red (`UnsupportedFormat`/`Parse` instead of
  `ZipBudget(RatioTooHigh)`); reverted, it is green again.

The seven temporary tracer tests that proved each extractor during development
were removed in favour of the fixture-derived suite.

## Gates

`cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` (CI's exact
invocation), and `cargo test` (1059 tests, 0 failed, 0 ignored) are all green.
Tests stay hermetic — no network, no Docker; the live-Solr differential is gated
behind `WAYFINDER_DIFF_SOLR=1`.

## Ponytails / out of scope

- Legacy OLE2 (DOC/PPT/XLS) is still `UnsupportedFormat`. `calamine` *can* read
  XLS; it is left for its own decision rather than bundled here.
- PDF remains unsupported (the `extract_corrupt_pdf` status divergence stays).
- Office metadata stays narrow by design (finding 125); reproducing Tika's full
  format-specific metadata set is explicitly not a v1 goal.
