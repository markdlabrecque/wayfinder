# #298 — advertise `search_api_facets_operator_or` (`{!ex}`/`{!tag}` on the wire)

The Drupal-side half of OR facets, on top of the server exclusion machinery
#295 landed in wave 1. Branch `markdlabrecque/issue-298-advertise-search-api`,
wave-4 branch **K** of the #289–#302 parity batch. The server needed no new
code — only a hermetic pin on the parser behaviour the tag relies on.

## Spec

The user-visible bug this closes: in a `facets`-module facet block set to the
OR operator, checking one value zeroed out its siblings, because every facet
was counted against the full `fq` set. #295 made the server capable of the
`{!ex}`/`{!tag}` dance; this issue makes the client emit it and advertise the
feature.

Two correctness facts from the client (`search_api_solr`
`SearchApiSolrBackend.php:3928–3935`), both load-bearing:

1. **The tag string is `facet:<search_api_field_name>`, not the mapped Solr
   field.** `search_api_solr` emits `addExcludes(['facet:' . $info['field']])`
   — `$info['field']` is the Search API field id — because the `facets` module
   defines the matching tag on the `fq` from the same Search API field name.
   Bug-compatibility means that exact string, built from the Search API field
   name, on both halves.
2. **That tag contains a colon.** `{!tag=facet:category}` / `{!ex=facet:category}`
   are bare local-param values; the server's `local_params::read_value`
   terminates a bare value on whitespace, never on `:`. Pinned hermetically
   rather than assumed (see below).

## Why no server change and no new fixtures

The wire shapes this emits are exactly the ones #295 captured and
differential-tested: `facet_extag_excluded`, `facet_extag_both_facets`
("the row that proves the OR-facet UI is reproducible"), `facet_extag_multi_tag`,
`facet_extag_ex_with_key` / `facet_extag_key_before_ex`. The Drupal module now
produces those shapes; the server already serves them. `ResponseParser` needs
no change: the response `facet_fields` block is keyed by the `{!key=<delta>}`
value regardless of `{!ex}`, so key-based resolution (#299) is untouched.
